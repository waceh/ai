### 개요

MCP Sampling은 **MCP** 서버가 자체 API 키 없이, 클라이언트를 거쳐 **LLM** 완성(completion)을 요청할 수 있게 하는 프리미티브입니다.

비유하면, "서버가 직접 전화를 걸지 않고 클라이언트에게 대신 전화해 달라고 부탁하는 것"입니다. 서버가 텍스트·이미지·오디오 기반 요청을 만들면, 클라이언트가 실제 LLM 호출 권한·모델 선택을 쥔 채 대신 실행합니다. 요청 전에는 사용자가 프롬프트·컨텍스트를 확인·수정·거부할 수 있고, 응답이 온 후에도 서버로 보내기 전에 다시 확인하는 **HITL** 단계를 거치는 것이 스펙 권고 사항입니다.

유의사항: MCP Sampling ≠ 서버가 자체 LLM을 호출하는 것이 아닙니다. 서버는 API 키 없이 클라이언트의 모델 접근 권한을 빌려 쓰는 것이며, 클라이언트가 항상 최종 통제권을 가집니다. 이는 서버가 중첩된 LLM 호출로 에이전트적 동작을 구현할 수 있게 해줍니다.

### 사용목적

MCP 서버 로직 안에서 LLM 판단(예: 요약, 분류)이 추가로 필요하지만 서버 자체가 별도 모델 API 키·과금을 관리하고 싶지 않을 때 씁니다.

### 동작/구조

서버가 sampling 요청(프롬프트·컨텍스트·모델 힌트) 생성 → 클라이언트가 요청을 사용자에게 보여주고 편집·승인·거부 받음 → 승인되면 클라이언트가 실제 LLM 호출 → 응답을 다시 사용자에게 확인 → 승인된 결과만 서버로 반환.

- **MCP**: Sampling이 속한 프로토콜
- **LLM**: Sampling으로 최종 호출되는 대상
- **HITL**: 요청·응답 양쪽에서 사람이 확인하는 권장 안전장치
